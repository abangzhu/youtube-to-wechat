# 自审与停止条件

适用于 article.md 的初稿、局部修订和交付检查。稿型及规则优先级见 [SKILL.md](../SKILL.md)，格式定义只维护在 [narration-and-formatting.md](narration-and-formatting.md)。

## 先核对事实和证据

- 每个重要数字、专名、引语和实验结论可定位回原始来源。核对发言人；人物多重身份分别对应，不能把 contributor、creator 都写成 founder。
- 比例和倍数用同一口径复算，说明分子、分母、时间及比较条件。2/16 到 3/48 是数量增加、通过率下降；不能把观察到的变化自动写成因果。
- 区分来源事实、个人判断、预测和编辑推论；保留决定结论的限定词、不确定性和适用范围。主体改变时重新标明归属。
- 来源本身存在错误时，核查与编辑注另行说明；不编造更精确的数字、公司名、日期、出处或收益承诺。
- 原始来源不完整时说明缺口，不能以文风完整掩盖证据不全。检查标题是否放大结论或错误归因给承载平台。

事实问题是必须解决的错误。未能核实的关键内容应暂缓采用、明确限定或向用户说明缺项。

## 再用读者视角检查

- 未看过来源的读者能否说清本文的主要发现、证据和意义？必要概念首次出现时是否有解释？
- 解释型稿件的演示段落遮住截图后是否仍能理解结论？保留必要原因和数据，删除依赖陌生界面的回放。
- 教程的必要前提、步骤、代码、结果是否齐全？不能为简短或禁用列表而破坏复现。
- 每个章节有明确作用；允许段落分别承担定义、证据、解释和应用，不要求每段都承诺收益。
- 是否遗漏会改变结论的反例或条件？是否塞入与主旨无关的履历、轶事和代码接线？

有具体卡点再精修相应段落。长句或省略本身不构成错误；以是否造成歧义、误读或额外理解成本判断。

## 最后检查表达与格式

减少无信息的铺垫、套话和重复，但保留必要的归因、真实不确定性和技术术语。可以使用服务语义的冒号、引号、连接词和对比；不追求某种词或标点零命中。

自动检查只辅助人工判断：

~~~bash
python /实际技能目录/scripts/check_article.py /任务目录/article.md --stage awaiting-title
python /实际技能目录/scripts/check_article.py /任务目录/article.md --stage ready
~~~

脚本只读，不提供全文件替换。它检查交付阶段所需的标题、来源注记、未完成占位和本地图片等，并在普通中文叙述中标出少量风格候选；代码块、内联代码、引语、URL 和标题不会被当作普通正文处理。它不验证源文忠实度或所有 Markdown 语法。

不要用 sed、全局标点替换或禁词替换来“修正”整篇文章。代码、链接、原文引用、标识符和 UI 标签属于受保护内容。保留代码原语法，中文解释放在代码块外或合法注释里。

## 验收阶段

- draft：检查当前已完成内容；允许待定标题和有明确说明的占位。
- awaiting-title：来源与正文已核对，标题候选可供选择；缺少正式 H1 和最终封面不算失败。
- ready：正式 H1 与用户选定标题一致；所请求的图片和其他交付物可用，图片对应正文、手机显示可读，来源注记完整。发布成功需要外部返回结果另行确认。

检查器不读取用户授权历史；标题是否已确认、图像是否说明了正确事实、正文是否诚实披露来源限制，仍需语义核查。

## 何时停止

完成事实核查、解决格式错误、消除重要理解障碍，并对每个剩余风格提示作出保留或修改判断后停止。无需强迫第二轮找出固定数量的问题。新改动只复查受影响内容；出现新的事实或结构问题时才扩大检查。

复杂任务可保存简短 self-review.md，记录关键核验、剩余限制和交付状态。简单修订可以直接在交付说明中汇报，不为证明工作而堆文件。
