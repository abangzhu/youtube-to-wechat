# 封面选择与验收

先准备方案和候选素材，等用户确认文章标题与正文后再生成最终 `cover.jpg`。已有明确确认无需重复询问。封面不能引入正文没有支持的结论、数字或人物背书。

## 两条路径

| 路径 | 适用情况 | 实现 |
| --- | --- | --- |
| A：来源图 | 人物、产品、现场或图表本身能让读者理解主题 | 取得原缩略图、网页图片、文档图表或视频截图，再选择合适裁切 |
| B：原创文字卡片 | 主旨主要靠一句观点或问题表达，或来源图信息杂乱 | 使用 [cover-card-template.md](cover-card-template.md) 的 HTML 模板，按内容调整 |

先看来源图再决定，不把“访谈一定用人像”“技术一定用渐变”当硬规则。选择应服务这篇文章与用户偏好；没有合适图时不勉强使用来源图。

## 获取来源图

YouTube 缩略图可以从页面元数据取得，也可以探测常见地址。下面只是候选，不保证该视频存在高清图：

```bash
curl --fail --location --output cover-source.jpg \
  "https://i.ytimg.com/vi/VIDEO_ID/maxresdefault.jpg"
```

若返回错误、占位图或低清图，检查页面实际提供的其他尺寸/缩略图，再考虑视频截图或模板。也可在当前 `yt-dlp` 支持的情况下使用 `--write-thumbnail --skip-download`；不默认带浏览器 cookies。

网页优先读取实际 `og:image` 或文中原图，解析相对 URL，检查内容类型、尺寸和画面。OG 图可能与正文无关，不直接当作已选封面。本地文档选择清晰且与主旨有关的图表；没有则用路径 B。

视频取帧、图像验证和裁切按 [visual-capture.md](visual-capture.md)。裁图保留理解所需的人物、图例和上下文，不把来源图改成误导性证据。

## 标题与输出

- `article_title` 是用户确认的正式文章标题。
- `cover_title` 是用于封面的短文案，可从文章标题缩写，也可沿用；不得改变论点、限定范围、语气强度或归属。二者记录在封面素材条目里，不能为排版偷偷修改 H1。
- 一行放不下时，先精简短标题或安排两行，再调整字号和间距。没有固定“超过多少字一律缩小/一律不许缩小”的规则；以实际显示可读为准。
- 默认可用约 2.35:1 的宽幅画布（如 900×383 CSS 像素）；平台、卡片位或用户要求其他比例时按实际要求调整，不能把经验尺寸当作永久平台规范。

保存 `cover.jpg`，原创卡片同时保留 `cover.html`；原图和裁切版本分别保存。按 [assets.json 契约](visual-capture.md#3-assetsjson-契约)登记路径、原图 URL/出处、时间戳、裁切变换、alt 与核验结果。

## 验收

实际打开输出文件，检查字形、缺字、截断、图像质量和图文一致性。按计划展示位置预览宽幅与可能的方形裁切，在缩略图尺寸确认核心标题或主体仍能识别。若平台可独立设置裁切，记录裁切位置；无法兼顾时另导出适配版本，不用全图藏字或无限缩字号来解决。

高分辨率只是提高清晰度，不会让比例过小的文字在手机上变大。用户未确认标题或正文时，保留方案与候选素材并按主流程交付待确认状态，不生成冒充最终稿的封面。
