# YouTube 来源获取与有限回退

先判断拿到了什么，再决定能写什么。下载失败、第三方空响应或浏览器超时，都不能证明视频没有字幕。本文件定义视频转录的获取优先级、来源状态和停止条件。

## 1. 保留原声材料，翻译另存

在可获取且覆盖相当的候选中，优先顺序是：**原声语言的人工字幕 → 原声语言的自动字幕 → 对原声音频做 ASR**。先核对实际口语语言与字幕轨道；多语言视频记录各段语言。自动字幕和人工字幕均可能出错，关键数字、专名和结论仍需核对声音或画面。

现成中文字幕若是译文，可以辅助理解，不能替代英语等原声材料充当逐字原文。原始文件保留不改，中文译稿和专名修订另存；只有译文可用时明确其性质，不将其冒充原文。取得更好的来源后另存版本，保留获取渠道与差异记录。

有 `yt-dlp` 时，先查看本机帮助和可用字幕轨道，再选择实际存在的语言代码：

```bash
yt-dlp --list-subs --skip-download "VIDEO_URL"
# 原声人工字幕；把 ORIGINAL_LANG 替换为实际轨道代码
yt-dlp --write-subs --sub-langs "ORIGINAL_LANG" --sub-format vtt \
  --skip-download -o "%(id)s.%(ext)s" "VIDEO_URL"
# 人工字幕不可用时，改取原声自动字幕
yt-dlp --write-auto-subs --sub-langs "ORIGINAL_LANG" --sub-format vtt \
  --skip-download -o "%(id)s.%(ext)s" "VIDEO_URL"
```

不默认读取浏览器 cookies。若认证确有必要，按当前环境权限与用户授权处理，不循环尝试解密失败的 cookies，也不规避访问控制。

取得 VTT 后运行一次解析即可保留文本和时间戳：

```bash
python scripts/parse_vtt.py --keep-timestamps "字幕文件.vtt"
```

解析器始终输出 `*_cues.json`，并输出一种文本：默认是 `*_parsed.txt`，加 `--keep-timestamps` 时是 `*_timestamped.txt`。原始 VTT 不变，默认不去重。已有目标默认拒绝覆盖；仅在明确要更新这些派生文件时使用 `--overwrite`。不要用去掉时间戳的阅读版覆盖原始来源。

## 2. `source.json` 的转录状态契约

`source.json` 保留视频标题、作者、URL、实际时长等元信息，并用 `transcript` 对象记录转录。未拿到的数据用 `null`，不要填猜测值。

```json
{
  "url": "https://www.youtube.com/watch?v=VIDEO_ID",
  "duration_seconds": 3600,
  "transcript": {
    "status": "unknown",
    "language": "en",
    "caption_type": "automatic",
    "channel": "yt-dlp",
    "local_path": "VIDEO_ID.en.vtt",
    "coverage": {
      "start_seconds": 0,
      "end_seconds": 3590,
      "gaps": [],
      "verification": "尚未核对片尾和中间缺口"
    },
    "checked_at": "2026-10-18T10:00:00+08:00",
    "limitations": [],
    "attempts": []
  }
}
```

`caption_type` 使用 `manual`、`automatic`、`asr`、`translation` 或 `unknown`。`channel` 写实际渠道，如下载工具、YouTube 转录面板、第三方服务或 ASR 工具名。`coverage.gaps` 记录已知缺口的起止秒数和原因；空数组只表示未记录到缺口，不能单独证明完整。

| status | 含义与可接受证据 |
| --- | --- |
| `complete` | 转录覆盖完整的有效口语内容；已核对开头、结尾、时间范围及可疑缺口，并记录依据。片头音乐或片尾静音不要求有字幕。 |
| `partial` | 已知缺少段落、只取得预览，或服务明确截断；记录已覆盖范围。 |
| `unknown` | 有文本但覆盖范围无法确认，或获取失败且无法判断源材料状况。 |
| `unavailable` | 当前来源及可用渠道无法提供所需转录，且有明确说明；写明是字幕轨道不可用、音频不可访问或其他限制。此状态不宣称永久没有字幕。 |

视频接近结尾的时间戳、服务返回 `hasMore: false`、字符数很多，都只是完整性线索。需结合实际视频时长、开头结尾语义和中间异常检查；低字符密度可能是静音或演示，高密度也可能是重复字幕。不要用固定字数阈值判定完整。

## 3. 有限回退顺序

每个失败渠道先识别原因。临时超时、限流等可按服务提示等待后重试一次；认证、权限和明确不支持的错误不重复撞。只有条件发生变化（恢复网络、切换合法可用渠道、工具更新等）才值得再次尝试。

1. **直接来源。** 下载工具失败后，用当前可用浏览器打开 YouTube 的转录面板，核对语言，按页面实际功能读取；遇到虚拟列表需滚动获取其余段落并检查边界。页面已有可访问的字幕数据，也可在工具支持范围内读取。不要依赖固定的内部 JSON 路径或注入请求拦截器。
2. **第三方字幕服务。** 直接来源仍取不到时，选择当前可访问的服务，先查看实际响应和使用条件。最多尝试两个独立渠道；避免轮询一串依赖同一上游的服务。记录服务名和验证时间，核对它提供的是原声字幕、自动翻译还是摘要。
3. **音频转录。** 有合法可访问的音频和当前环境可用的 ASR 能力时，可以生成带时间戳转录。长音频分段要保留重叠区的核对记录，检查拼接缺口；关键术语和数字回听。成本或上传要求超出已有授权时先处理该限制。

一条浏览器回退示例是 Tactiq 的公开转录页面：

```text
https://tactiq.io/tools/run/youtube_transcript?yt=URL_ENCODED_VIDEO_URL
```

这是可供探测的入口，**不是可用性保证**。按实际浏览器工具文档打开页面，检查加载状态；若页面仍使用 `#transcript`，可在工具允许的页面读取接口中运行：

```javascript
() => {
  const el = document.querySelector('#transcript');
  return {
    found: Boolean(el),
    text: el?.innerText ?? '',
    pageTitle: document.title
  };
}
```

空结果只说明当前页面没有返回文本。检查加载、错误提示或截断标记后，再决定换渠道；不要把空容器翻译成“视频无字幕”。没有时间戳的文本按段落编号保存，不能编造时间戳。

## 4. 故障分类与停止

| 现象 | 能得出的结论 | 下一步 |
| --- | --- | --- |
| DNS、代理、MCP 连接超时 | 当前环境或工具失败 | 修复明显配置问题或换已可用工具，保留来源状态 `unknown` |
| 下载格式、PO Token、挑战或登录错误 | 该下载请求未成功 | 检查当前工具说明，有限回退；不推断字幕不存在 |
| 第三方空结果、付费预览、服务报错 | 该服务未提供完整转录 | 分别记录 `unknown` 或 `partial`，换独立渠道 |
| YouTube 明确显示当前字幕不可用 | 当时该视频/语言轨道不可用 | 若有音频 ASR 则继续；否则记录带时间的限制 |
| 所有已授权可用渠道耗尽 | 当前任务缺少足够来源 | 保存已取得材料与 attempts，说明缺口并停下依赖完整来源的写稿 |

`attempts` 每项记录渠道、时间、环境/工具版本（能查到时）、结果和错误摘要，不记录 cookies、令牌或带凭据的链接。历史故障只适用于当时条件，不把某服务永久列为禁止路径；恢复后可按有限回退策略再试。

完整来源拿不到时，可以继续核对标题、人物身份和已覆盖片段，但不能交付一篇假定涵盖全片的稿件。向用户说明实际状态与缺口，再让用户选择提供转录、允许只处理已取得片段，或改用指定二手资料。用户已允许的范围无需重复确认；不得默默把二手报道写成亲自核对过的视频内容，也不承诺字幕必定会在若干小时内出现。
